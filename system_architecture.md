# Asset Architecture

## Non-destructive text effects

Typography → Effects provides 34 visual treatments and an ordered Applied Effects stack. Each text layer stores optional `textEffects` with stable IDs, visibility, intensity, seeds, effect-specific settings, gradient stops and fill image sources. Reorder, duplicate, remove and live controls use the existing document/history updates. Original / No effects removes the stack without replacing the text. Image/texture fills require a source; their gallery thumbnails use a sample only.

[textEffects.ts](./src/app/lib/textEffects.ts) implements deterministic alpha-aware masks, textures, glyph-distance relief/thread shading, materials, displacement, depth, light and fills. Ordered operations work on the preceding result; intensity blends premultiplied colour and coverage. Zero/hidden effects bypass rendering. Cracks remove coverage, fills remain clipped, and embroidery uses local glyph geometry rather than a rectangular overlay.

[TextEffectsArtwork.tsx](./src/app/components/builder/printsStudio/TextEffectsArtwork.tsx) captures the existing HTML/SVG text markup, retaining fonts, curve paths, decorations, outlines and spacing. The original editable text remains the source of truth; the overlaid canvas is disposable rendering, not a saved replacement. Source captures are reused for effect-only edits. Font readiness and distinct loaded-face changes invalidate captures, while equivalent faces inserted by font embedding do not create recapture loops. Failures remain visible with Retry and block export rather than silently dropping effects.

[textEffectRendering.ts](./src/app/lib/textEffectRendering.ts) uses a module worker and newest-pending-job queue per renderer. Stale results cannot overwrite newer settings. Captures and fill images are bounded to 1024px on their longest edge (text at up to 2× CSS resolution); this is the current effect-rendering resolution ceiling, including exports. Padded capture grows with stacked expanding effects. Recursive group padding, warp meshes, alpha selection bounds and merge captures include this overflow without changing the original text layout box. Legacy shadow and flips compose outside the effects; warp consumes the resulting artwork.

The shared renderer covers garment sides, groups, editable Asset Builder source and later-page previews. Finished asset placement and explicit Merge may flatten the visible result, while saved Asset Builder source retains editable wording and the stack. Readiness checks await both image filters and text effects before captures.

Validation: `node --test scripts/test_text_effects.mjs`, `node scripts/test_text_effects_browser.mjs`, and `node scripts/test_text_effects_editor.mjs` cover presets/controls, masks, geometry, stack order, live input, retries, source editing, grouping/warp, transparent export, history, Asset Builder and front/back project persistence. Browser suites use `CERIGA_BASE_URL` (default port 5189).

## Non-destructive image filters

Assets → Upload image includes a dedicated Image → Filters panel with Original / None followed by 34 actual-image thumbnail previews. Each image layer persists optional `imageFilter` settings independently of manual image adjustments. Intensity updates on input; selecting Original removes only the preset. Filter-specific sliders/colours are described by the shared catalog, and locked images cannot change settings.

[imageFilters.ts](./src/app/lib/imageFilters.ts) supplies deterministic, alpha-preserving pixel algorithms and control defaults. Geometric settings use a 600px reference so previews and placed images agree. [imageFilterRendering.ts](./src/app/lib/imageFilterRendering.ts) caches decoded source pixels and full-strength effects, uses a module worker for processing, and blends cached original/effect pixels for live intensity. Working images are capped at 1600px on the longest edge; thumbnail processing uses 96px. These are bounded render caches, not replacements for the original uploaded content. Original and zero intensity bypass processing entirely.

[FilteredImage.tsx](./src/app/components/builder/printsStudio/FilteredImage.tsx) is shared by ordinary and recursively grouped image layers, including Asset Builder and front/back previews on later pages. Presets render before the existing adjustment/effect wrapper, so exposure, contrast, colour adjustments, grain, sharpen and transforms remain independently editable. A pending settings change retains the previous result until current pixels arrive. Decode/processing errors retain the source and expose Retry; captures fail rather than silently saving an unfiltered fallback.

Filter settings invalidate warp and alpha-bound signatures. Warp sources, merge and artboard export wait for current filtered pixels and nested warp readiness. Editable asset source, project persistence, duplicate and Undo/Redo retain settings; an intentional merge or finished-asset placement captures the rendered appearance.

Validation: `node --test --test-concurrency=1 scripts/test_image_filters.mjs scripts/test_image_filters_browser.mjs` checks all presets/controls, deterministic texture, alpha, reference scaling, bounded-size processing, actual rendered pixels, intensity caching, adjustment composition, nested grouping/warp/export, failed-render retry, live controls, asset source editing, merge/duplicate and front/back Review/Delivery persistence. The browser test accepts `--ui-only` for targeted editor checks and `CERIGA_BASE_URL` for the running Vite origin (default port 5189).

## Asset Builder workspace

Asset Builder is a document mode within Prints & Design, entered through Assets → Create Asset or Edit Asset. It reuses `PrintsDesignPreview`, the existing tools, sidebar and Layers panel. The garment is replaced by an explicit 32–4096-pixel transparent artboard (square, portrait, landscape or custom dimensions); garment-side and process controls are hidden. The checkerboard is a display-only sibling of the export region, not an artwork layer.

`printsStudio/useAssetWorkspace.ts` owns the editable asset document, selection, source dimensions, dirty baseline and a separate 100-entry Undo/Redo stack. Builder routes editing to this document while retaining garment front/back layers, history, side and viewport. `PrintsStudioProvider` scopes tool preferences by document ID. Back prompts before discarding changes; browser unload is protected, and IndexedDB recovery drafts survive interrupted sessions. Draft scopes are isolated by authenticated account or guest, including account changes during asynchronous saves. A failed render/storage/cloud save leaves the source editable.

`lib/exportAssetArtboard.ts` waits for artwork, nested source, warp, fonts and images, then captures exactly the artboard dimensions as transparent PNG with overflow clipped and all editor chrome excluded. Saving stores both that preview and the complete editable source via `lib/assetLibrary.ts`, restores the garment, inserts a proportional image on the original garment side and selects it. My Assets supports thumbnails, click/drag placement, reopening source, Save Changes and Save as New Asset. Existing placements remain snapshots; editing a library source does not silently replace earlier garment placements.

Guests save durably to IndexedDB on the current browser origin. Signed-in saves require confirmed Supabase writes to `asset_projects`, with recoverable pending local copies on failure. Apply the migration documented in [supabase/README.md](./supabase/README.md) before using account sync. Backend deployment and real authenticated cloud round-trips are not covered by mocked storage tests.

`lib/designGroups.ts` and `DesignGroupArtwork` retain child objects and render them recursively. Layers support names, visibility, position locking, reordering, duplicate, delete, multi-select, grouping, ungrouping and merge. Grouping requires adjacent visible unlocked compatible artwork to preserve stacking; garment-bound/system layers are excluded. Ordinary ungroup restores source coordinates; resized, cropped, flipped, warped or distorted groups retain editable single-child transform envelopes. Reset envelope transforms before removing an envelope; group opacity/shadow/spatial filters must be reset before ungrouping to preserve overlapping compositing. Duplicating groups recursively assigns new child IDs to isolate SVG filters and capture signatures.

Validation: `node --test --test-concurrency=1 scripts/test_asset_document.mjs scripts/test_asset_library.mjs scripts/test_asset_workspace.mjs scripts/test_design_groups.mjs` covers account/draft isolation, mocked sync failures, actual editor front/back/history preservation, artboard dimensions, transparent drawing export, naming, layer visibility/duplication/deletion, source editing, save-as-new, drag/drop, failed-save retry, reload recovery and mobile mode. Group tests additionally compare rendered pixels across artwork types and complex transforms.

## Brush presets, textures, spacing and scatter

All 41 presets (the original nine plus drawing/ink, traditional paint, graphic, distress, stitching and embroidery additions) share arc-length stamps in `lib/drawingBrush.ts`. Preset metadata supplies contextual controls; each stamp changes geometry, coverage or thread structure, not the user's texture. Spacing is 5–500% of brush diameter, with a half-logical-pixel minimum interval; thread length/density also influence thread intervals. Scatter exposes spread (0–300% of brush size), count (1–12), size (10–200%) and per-mark opacity. Whole-stroke Opacity remains separate. Stroke-local seeds keep stamp distribution and irregular geometry stable during repaints; Randomise changes the recipe seed for drips and distress. Pressure, tilt, angle, rotation, taper, stabilisation, smoothing, symmetry and garment/Asset Builder clipping remain in the shared pipeline.

`lib/brushTextures.ts` independently supplies 47 texture choices including Smooth, the three legacy grains, structured fabrics, art/print/distressed masks and Custom Texture. Legacy `canvas`/`denim` IDs remain Canvas Weave/Denim Twill; `canvas-fabric`/`denim-fabric` are the new options. Weaves, knits, loops, pores, cracks, scratches, ordered dots and multiscale noise use distinct periodic structures. Scale, strength, density, rotation and contrast operate on destination-out alpha masks, never an RGB overlay. Local PNG/JPEG/WebP uploads up to 8 MB are decoded with bounded dimensions and downsampled to 512 pixels; custom black removes ink, white retains ink, and transparent regions retain ink even with Invert. Four decoded masks and twelve tiles are cached. Uploads finish loading before becoming active; missing custom data safely leaves the ink unchanged.

`BrushSettingsPanel` renders its live preview with the same stroke engine as the drawing canvas. Preset changes retain independently selected texture settings and custom source. Every setting redraws the active stroke immediately. Only compatible smooth drawing pens can auto-convert to quick shapes; textured, spaced, scattered and specialist brush strokes retain their appearance. Finished strokes retain existing raster-layer persistence and Undo/Redo, rather than retroactively changing with the next brush recipe.

Distress Brush offers Paint worn marks or Remove from drawing layers. As requested, Remove only affects visible, unlocked drawing layers on the current garment side—not shapes, image assets or the separate distress tool. The clipped/symmetrical brush alpha is mapped back to source pixels by `lib/brushRemoval.ts`, respecting rotation, flips, perspective, warp and crop, with one history commit per gesture. Fully erased drawings are removed; other layer properties remain intact. The existing Distressing system is unchanged.

Validation: `node --test --test-concurrency=1 scripts/test_brush_distribution.mjs scripts/test_drawing_stabilization.mjs scripts/test_brush_presets.mjs scripts/test_brush_textures.mjs scripts/test_brush_removal.mjs scripts/test_brush_editor.mjs` covers event-independent spacing, stable scatter, all preset/control renderings, distinct texture masks and controls, custom-mask inversion/clipping, live previews, independent selections, alpha removal/transforms, Undo/Redo and mobile controls.

## Simplified artwork controls

The Border settings panel is hidden for shapes, patterns and distressing (including the system distress drawing layer); existing artwork borders remain unchanged. The shared quick-selection toolbar no longer exposes Adjust or Outline buttons on desktop or mobile. Image adjustments and image borders remain available in the main sidebar; text Effects remain available in the quick toolbar. `node scripts/test_print_controls.mjs` verifies these controls on desktop/mobile and checks that viewing them does not change artwork.

## Shapes, editable paths and shape effects

Shapes & Lines retains its original eight choices and adds 20 geometric/graphic shapes plus Custom Polygon. `lib/shapeGeometry.ts` supplies procedural vector paths, contextual parameter metadata, cubic conversion and compound contours (including ring holes). Untouched legacy shapes retain their original SVG markup. `shapeParameters` remains editable until conversion to `shapePath`; optional independent `shapeFillColor` and `shapeStrokeColor` fall back to the existing colour. `shapeFilled` still defaults to false. All closed contours support Solid fill; open lines, waves, spirals, arcs and squiggles do not. Outline thickness can be zero. Dimensions, opacity, rotation and both flips continue to use the standard layer controls.

Custom Polygon starts a transient canvas tool: click successive points and click the first to close, Backspace/Delete removes the last draft point, and Escape cancels. Convert to Editable Path materializes editable cubic anchors without baking rotation, flips or effects. `ShapePathEditor` supports Shift-click multiple selection, dragging points and curve handles, double-clicking a segment to add an anchor, Curve/Corner controls, Delete and arrow-key movement. `shapePathEditing.ts` uses De Casteljau splitting to preserve curves and inverse flip/warp/perspective mapping for pointer gestures. Draft drags render live but commit only once to history. Normal resize/rotation handles are hidden only while Edit Path is active; editing chrome is excluded from captures and exports.

Selected shapes expose Effects within their properties, not a new sidebar category. `shapeEffects` uses the existing sequential worker engine and stack controls, with a shape-specific catalog of 26 treatments including Gradient, texture/cutout, lighting, depth/material, masked image fills and graphic effects. Users can reorder, duplicate, remove, toggle and adjust effects independently. Closed-shape gradient/image/texture selection enables the base fill, and image/texture choices are hidden for open paths. Gradients support multiple stops, linear/radial/conic projection, angle and position; image/texture sources include uploads and available assets, with crop, positioning, scale, rotation and opacity controls. Shape thumbnails, labels and contextual controls remain separate from the unchanged text catalog.

Only the effects presentation is rasterized; source vectors, parameters, path nodes, fills and ordered effect settings persist with normal artwork and Undo/Redo. Source signatures include all shape properties, invalidating warp and painted-pixel hit captures after edits. Capture padding includes Bézier control hulls outside the original shape dimensions and cumulative expanding effects, including grouped artwork. Garment and Custom Area masks still clip the final layer. Asset Builder, saved previews and exports use the same renderer.

Validation: `node --test scripts/test_shape_geometry.mjs scripts/test_shape_path_editing.mjs scripts/test_shape_effects.mjs scripts/test_shape_editor.mjs` covers the catalog, contextual controls, legacy conversion raster parity, independent paints, compound holes, curve splitting, transformed anchor gestures, canvas polygon creation, effect controls/order/clipping and preserved sources. `test_shape_fill.mjs`, `test_artwork_selection.mjs` and the existing text-effect tests cover shared behavior regressions.

## Layer merging, reversible cropping and saved previews

The Layers panel merges visible, unlocked, adjacent artwork on the same side and print method into one PNG image layer. System drawing/distress layers and distress assets are protected. `lib/mergeDesignLayers.ts` captures only selected artwork through the live compositor at 2× resolution, waits for fonts/images/warp capture readiness, excludes all editing chrome, preserves transparency and trims the bitmap while retaining its position. One state replacement keeps the originals in Undo; asynchronous changes or rendering failures abort without deleting layers. The flattened result retains image editing, including crop and both flips; original components are recoverable through Undo rather than ungrouping.

`lib/artworkCrop.ts` normalizes crop insets to retain at least 1% on both axes. `printsStudio/CropEditor.tsx` supplies eight handles and a movable rectangle, including keyboard adjustments and projective pointer mapping. Prints and label/packaging editors keep draft crop state separate: Apply commits once, Cancel/Escape discards, and Reset clears the draft before Apply. Source content is unchanged. The shared asset surface clips the final warped artwork before perspective projection; flips transform content, not crop boundaries. Crop handles sit outside garment masks and are excluded from raster capture.

`printsCanvasSize` persists the logical editor frame in builder state. Read-only and resized previews scale the complete garment/artwork scene together, preserving positions, font sizes and masks. Legacy projects without a recorded frame use a 520×560 fallback in project cards until opened in the editor. `ProjectGarmentPreview` uses `PrintsDesignPreview`, including saved front/back artwork, rather than a reduced renderer. Review, delivery, checkout, order details, project cards and garment version thumbnails share that renderer and saved design state. Front/back refers to artwork sides; underlying SVG packs still provide their existing garment geometry. Selection, drawing and crop chrome are not rendered in read-only previews.

Validation: `node scripts/test_artwork_crop.mjs` covers crop geometry, rotated/scaled/perspective pointer gestures and both label/packaging layouts. `node scripts/test_design_composition.mjs` compares flattened pixels, checks merge restrictions, warped/cropped assets, both sides, preview scaling and generic non-destructive crop. `node scripts/test_design_workflow.mjs` checks atomic merge Undo/Redo, crop Undo/Redo with unchanged source, desktop/mobile Review, both artwork sides in Delivery and restoration on return to the editor without submitting an order. Authenticated cloud ordering and PDF export require separate verification.

## Artwork selection and hit testing

Prints & Design and Asset Builder use one transform overlay, positioned by `DesignAssetSurface`'s current painted-pixel bounds. The full layer wrapper is layout-only (`pointer-events: none`); it has no selection handler or drag ring. Only actual editing controls opt back into pointer events. The former `.canvas-element-held` rectangular box shadow and the redundant empty handles container are removed.

`lib/artworkHitTesting.ts` registers non-DOM hit tests in a weak map. Canvas pointer routing checks rendered alpha in stacking order, falling through transparent holes to lower layers. The shared alpha capture supplies both bounds and hit data; resize, crop, source, Custom Area anchor and warp changes invalidate obsolete samples, and cancelled captures cannot restore them. Sampling accounts for current dimensions, rotation, perspective, garment/part masks and opacity. Unavailable or empty raster data never falls back to an oversized rectangular hit target. Text remains editable, and pointer capture still belongs to the selected layer during dragging. Transform, crop, distortion and warp controls retain their own handlers.

`node scripts/test_artwork_selection.mjs` exercises large-to-small resize, transparent and overlapping artwork, drag/resize controls, one selection outline, rotation, perspective, crop, warp, groups, editable text and deselection. `test_design_workflow.mjs` selects painted pixels rather than clicking a layout rectangle and verifies merge/crop Undo/Redo and saved previews.

## Artwork flipping

Both editors persist independent optional `flipHorizontal` and `flipVertical` flags (missing means false). Shared `FlipControls` exposes both axes in sidebar, compact inline and pattern controls, with pressed states and lock protection. `lib/artworkFlip.ts` applies center-based local-axis reflections before rotation/projection/warp. Text flips its complete body, including lists and decorative lines. Images, colour masks, drawings, shapes, distress and patterns use the same reflection. Custom Areas reflect the complete boundary, fills and outline once; editable anchors and Bézier handles use the same inverse-mapped reflection. Garment/part masks stay fixed. Warp and visible-bounds signatures include both flags so toggling either refreshes captured artwork. Regression coverage: `node scripts/test_artwork_flip.mjs`.

## Editable pattern fills

`printsStudio/PatternGraphic.tsx` and `lib/patternGeometry.ts` share SVG repeats between panel previews, standalone patterns and Custom Areas. Repeat coordinates use actual artwork dimensions, so non-square areas do not stretch dot circles or diagonal angles. Scale, spacing, rotation, count, thickness and seeded dot randomisation are optional `DesignElement` fields; colour and opacity retain the existing fields. `PatternControls.tsx` edits these live in the Patterns panel. Seeded, periodically wrapped strata keep random dots stable across colour/opacity changes and avoid overlaps across repeat boundaries. Warp/selection render signatures include all pattern settings.

Dragging a pattern uses the existing asset MIME plus `application/x-ceriga-pattern` for hover detection during protected browser drag events. `useGarmentPatternTargets.ts` builds visible per-part alpha masks from the preview's stable layer IDs, SVG screen transforms, split-side clipping and construction stacking order. Higher sections occlude lower sections. Hit testing and highlights use those masks rather than bounding rectangles. Each applied fill saves `patternTarget`; current part bounds and an outer `DesignAssetSurface` mask are resolved at render time. Pattern controls transform the repeat, not its clipping boundary. Missing target sections hide their fills. Masks regenerate on preview mutations, resize and garment-side changes; existing floating artwork remains unchanged.

Closed, visible, unlocked Custom Areas take precedence when their cubic path contains the inverse-mapped drop point on visible fabric (`Path2D` containment accounts for resize, rotation, flips, perspective and warp). Drops replace the area's fill, not its anchor geometry or whole-area flip flags; the shared renderer stays inside its cubic clip and whole-garment mask. Outside drops create nothing. Pattern settings and target IDs use the existing JSON design-state persistence and undo history. Generated patterns remain SVG geometry; custom repeats store their source image independently of repeat settings.

`lib/patternCatalog.ts` defines 42 entries: the five legacy styles, 36 new geometric/fashion/graphic/organic styles and Custom Pattern. `lib/generatedPatterns.ts` adds bounded, seeded procedural motifs and periodic edge replicas without changing the legacy geometry branch. Palette labels and thickness/roughness/variation/randomisation flags drive pattern-specific controls. Primary paint comes from `color`; additional colours live in `patternColors`. Horizontal/vertical spacing, repeat angle, scale and amount remain independent layer properties. Randomise changes only the seed, preserving palette and settings.

`PatternLibraryPanel.tsx` provides categorized SVG thumbnails, editable type switching and a draggable configured preview. `lib/patternEditing.ts` validates an appearance-only whitelist in drag payloads: settings, palette, source, opacity and artwork flips can transfer, but layer identity, placement and target geometry cannot. Custom Area targets preserve their existing whole-area flips so a fill drop cannot move their boundary. Dropping a preset resets old fill settings; dropping the configured preview carries its settings to the new part or Custom Area. Warp-source signatures include every new repeat setting.

Custom sources may come from an upload, previous uploads, My Assets/Asset Builder previews or a compatible visible layer. Layer capture uses the existing readiness-aware `layerRenderer` with one layer and leaves the source layer untouched. Sources are snapshots, not live links to later edits of the original asset. Grid, Brick, Half-Drop and Mirror use exact lattices; Random uses seeded stratified position, rotation and per-element minimum/maximum scale. Random-only controls are hidden for exact repeat modes, and scale ranges cannot invert. Source images preserve aspect ratio and transparency. Saved assets and project JSON retain the image, repeat type and all settings non-destructively.

Validation: `node scripts/test_pattern_geometry.mjs` covers shared geometry/rendering; `node scripts/test_patterns_browser.mjs` checks all eight hoodie targets and pixel-disjoint masks, real panel drag/drop, live controls, stable randomisation, fixed masks, Custom Area anchors, undo/redo, side isolation, resizing and JSON serialization. `node scripts/test_generated_patterns.mjs` rasterizes every added type and checks determinism, periodic replicas, safe sources and all custom repeat geometries. `node scripts/test_pattern_editing.mjs` verifies appearance-only drag payloads, source retention, type changes and immutable target geometry. `node scripts/test_pattern_library_editor.mjs` exercises all 42 types, contextual controls, palettes, live randomisation, scale ranges, all source routes, guest asset save/reopen and configured drops onto garment parts and Custom Areas. `CERIGA_BASE_URL` selects the running server (pattern browser tests default to port 5189). Existing Custom Area tests remain regression coverage. Authenticated cloud save/reload and PDF export require separate verification.

## Advanced Custom Area paths

`lib/customAreaGeometry.ts` retains legacy polygon points and extends each local-pixel anchor with optional absolute `in`/`out` Bézier handles and a `linked` flag. Explicit `customAreaViewWidth`/`customAreaViewHeight` preserve the reference frame through editing and resizing. Closed paths render as SVG `M/L/C/Z` geometry; their source anchors remain editable JSON rather than flattened artwork.

`CustomAreaPathEditor.tsx` provides cursor-preview creation, automatic editing after closure, modifier-key multi-selection, anchor dragging/nudging, Corner/Smooth conversion, linked or independent handles, direct segment bending and shape-preserving De Casteljau insertion from the hover plus. Delete/Backspace removes selected anchors with a three-point minimum, never the whole area. Pointer gestures preview transiently and commit once; cancellation restores committed state. Closure and duplication submit selection with artwork atomically. Unchanged rounded dimension inputs do not create hidden resize/history entries. Normal transform controls hide during Edit Path and return when it ends.

Point mapping accounts for both flips, resizing, rotation, perspective and warp. Ordinary out-of-frame edits rebase the local geometry without moving world-space anchors; deformed areas keep their stable frame. Capture padding includes out-of-frame control hulls, and both classic/generated patterns extend coverage without changing repeat phase. `WarpedArtwork` signatures include curves, reference dimensions, fill placement, textures and outlines.

`CustomAreaGraphic.tsx` clips solid/gradient, pattern, image and texture fills to the same cubic boundary. Image/texture scale, rotation, position and opacity remain editable through `CustomAreaAppearanceControls.tsx`, including preset textures and raster texture uploads. Choosing colour, image or pattern clears competing fill sources; textures can overlay the current base fill. Optional solid/dashed/dotted outlines are inset and clipped, with editable colour, thickness and opacity. Entire-area move, resize, rotate, flip and duplicate retain curves. Locked layers disable path and appearance edits.

## Editable typography and drawing shapes

Text remains a `DesignElement` with its content and visual properties stored as editable fields. `printsStudio/TextArtwork.tsx` renders those fields for the Prints & Design canvas and the shared label/packaging canvas; styling is not baked into the wording or converted to an image. Keep the text renderer, canvas editor controls, and `WarpedArtwork` source signature in sync when adding properties so edits redraw immediately and warped text refreshes correctly. Text editing continues to update the original `content`.

List formatting is stored per text line. Both the multiline Typography settings input (`TextListInput`) and the on-garment textarea keep visible bullets/numbers in their editing drafts: typing `-` displays a bullet, typing `1.` starts numbering, Enter continues the list, and Enter on an empty item exits it. Ordinary Enter adds a newline rather than prematurely placing an asset; Add (or Ctrl/Cmd+Enter) places settings text. `formatTextListInput` restores visible markers when reopening canvas text. `parseTextListInput` separates the prefixes from editable wording and per-line metadata on placement, blur, or selection change, preventing duplicate rendered markers. Pasted mixed lists and markers inserted before existing wording are supported; deleting a marker removes that row's list formatting. Escape restores the original wording and list formatting. Marker conversion and Enter commit the textarea value before synchronously restoring the caret, preventing rapid typing from racing deferred selection updates. Curved text wraps each content line into native SVG text paths using the selected font's measured advances and spacing; font loading refreshes those measurements. Circle rows have distinct radii with sufficient path length, and alignment offsets remain within each path. Curve spacing does not affect straight text. These layout calculations never replace the source wording with an image.

Arc amount controls the bend angle smoothly, with layout height allowing for the arc depth. Circle text distributes native glyphs with SVG spacing-only adjustment, including a closing seam gap; even two-character text spreads around the circle rather than clustering at the seam. A minimum usable sweep prevents glyphs disappearing at low circle amounts. `textCurveControls.ts` shares circle sizing between sidebar and inline controls: radius 32–160px with 1px increments, an initial radius inferred from the existing box, no dimension reset on amount changes, and a saved original box restored when returning to arc or turning the curve off. The anchor and source wording are preserved. `node scripts/test_text_curve_controls.mjs` covers these transitions; browser tests cover circle coverage, seams, and real editor mode switching.

Selection measurements and warped rendering share the artwork source signature so typography, decoration, curve and shadow changes invalidate both. Outline thickness controls preserve outline-only mode. New text outline defaults are 0.25px with a 0–4px slider in 0.05px increments; decorative lines default to 0.5px with a 0.1–4px range. Explicit saved thicknesses and non-text borders are unchanged. SVG decorations inherit the text colour from the parent text node while glyph fill/stroke live on the text path, keeping underline and strikethrough visible and correctly coloured even with hollow glyphs. `node scripts/test_text_typography_browser.mjs` checks actual browser geometry, path capacity, text styles and outline/decoration pixels; the typography and list-editing Node test files cover rendering and editor behavior. With the app running, `CERIGA_BASE_URL` selects the server for `node scripts/test_text_editor_browser.mjs`, which exercises rapid typing, list exit/cancellation, anchored alignment and editing multiline curves in the actual builder.

Text shadows use the per-element SVG filter from `PrintsDesignStep.tsx`, applied to the rendered glyphs before element rotation or warp. The hold-to-recognize QuickShape path in `PrintsDrawLayer.tsx` commits the clean recognized preview as soon as the stationary hold is detected; an eventual pointer-up must not commit a duplicate.

### Current high-neck Scuba

The original source is `src/assets/studio-hoodie/hoods/high-neck-scuba-20260922/scuba/source.png`. The pale zip-hoodie photo informs construction only; no reference pixels or garment silhouette are traced. An original symmetric Canvas raster defines a volumetric paneled crown, recessed curved opening with binding, raised chin rim and tapered collar. No drawstrings, zipper, branding, shading or texture are added. All SVG path geometry is generated by Potrace.

`bodyRelativeScuba` sizes the crown from each fit's chest; `necklineAttachment: true` retains the actual neckline span instead of creating shoulder extensions. Traced crown widths are 640/572/614/551/472px and attachment spans 414/386/390/423/396px for Boxy/Cropped/Baggy/Regular/Slim. Heights match Regular Hood. The lower raster mapping uses the source collar attachment span, not the crown extrema; mapping those extrema to the neckline creates vertical slivers. The upper 68% preserves the opening shape. Separate fabric and pure-black ink groups retain hood-only colouring.

Conversion: binary 2048px source, contrast 1.35, luminance >=246 transparent and <=120 opaque with a linear ramp; alpha masks upsampled 3x and thresholded at 128. Node Potrace uses mask negation plus `blackOnWhite: true` for the requested ink polarity, rather than Python's Bitmap inversion call. Settings are minority turn policy, turdsize 4, alphamax 1 and opticurve. Both groups have even-odd fills and a source-sized viewBox. Regular Hood supplies line-quality and attachment benchmarks only.

Generate with `node scripts/collar/create_hood_collection.mjs --high-neck-scuba`; validate installed assets with `--high-neck-scuba --validate --live`. Publish with `node scripts/collar/publish_rebuilt_hoods.mjs --high-neck-scuba`. ## Hoodie fit packs

The hoodie builder uses five raster-first fit packs: `boxy`, `cropped`, `baggy`, `regular`, and `slim`.

- Boxy generation artifacts live in `src/assets/studio-hoodie/`.
- Other fit artifacts live in `src/assets/studio-hoodie/fits/<fit>/`.
- Live builder SVGs live in `src/assets/hoodie-test/<part>/`.
- Boxy uses untagged filenames; other fits use `Part (<fit>).svg`.
- Every baseline Set-in fit must export exactly eight parts: Body, Hood, Kangaroo pocket, Left sleeve, Right sleeve, Left cuff, Right cuff, and Rib hem.

`scripts/collar/pack_hoodie.mjs` keys the white background, traces construction ink with Potrace, derives registered fabric masks, validates part completeness and cuff symmetry, and writes `mockup.json`.

Fabric masks form an exact exclusive partition of the non-ink garment interior. A multi-source region assignment gives every fillable pixel to exactly one component, while construction-line pixels remain reserved for the fixed black outline layer. Generated packs must report zero missing, overlapping, and overflowing fill pixels; do not reintroduce per-part dilation or colour construction-line pixels.

`scripts/collar/export_hoodie_test.mjs <fit>` publishes generated parts to the live builder directories.

`scripts/collar/validate_hoodie_pack.mjs` verifies all five packs have eight editable SVGs. Each SVG contains:

1. A first `#000000` fabric group recoloured by `tintPotraceSvg`.
2. A second `#141414` construction-ink group that remains fixed.

Both groups use even-odd fills and the same 2048×2048 viewBox so parts remain registered.

The shared hoodie design language requires an upright hood continuously joined to the neckline, matching rib-knit cuff and waistband construction, and fit-specific silhouette changes without changing seam or line-art style.
